## 0. Decisions taken in this phase (summary)

| topic | decision |
|---|---|
| Content format | JSON files under `content/`, validated by Zod at build. MDX is NOT installed in v1: no page has long-form body copy, and JSON keeps Haiku edits mechanical. Revisit only if a case-study body is added. |
| Theme | Dark only in v1. Light tokens stay documented in DESIGN.md, not shipped. `color-scheme: dark` on `html`. |
| Source dir | `src/` layout (`src/app`, `src/components`, `src/lib`); `content/`, `public/`, `drizzle/`, `scripts/`, `e2e/` at repo root. |
| Rendering | Every page is static (SSG). `/` and `/portfolio/[slug]` are prerendered; `dynamicParams = false`. Only `/api/*` runs on demand (Node.js runtime). |
| Card to detail transition | React `<ViewTransition>` with Next.js `experimental.viewTransition` and a shared `name` per project cover. Motion `layoutId` cannot survive an App Router page swap. |
| Comments moderation | Pre-moderation: new comments are `pending`, only `approved` render. Moderation is SQL in the Neon console. No admin route, no admin UI. Owner gets a notification e-mail per new comment. |
| Comment images | Deferred. Not built in v1, upload field not rendered. Spec for Vercel Blob kept in section 6.8 for a later opt-in task. |
| Rate limiting | Postgres fixed-window counters in Neon (same DB), IP stored only as salted SHA-256. Contact falls back to an in-memory best-effort limiter if the DB is not configured. |
| ORM | Drizzle ORM over `@neondatabase/serverless` HTTP driver (`drizzle-orm/neon-http`), migrations as SQL files generated by `drizzle-kit`, applied by the user locally. |
| CSP | Static header CSP without nonces (nonces force dynamic rendering). `script-src 'self' 'unsafe-inline' 'wasm-unsafe-eval'`. Justified in section 8.2. |
| Analytics | None in v1 (keeps CSP and LCP path clean). |
| UI microcopy | One typed module `src/lib/copy.ts` holds every pt-BR UI string from DESIGN.md plus the additions in section 12.2. Owner data lives in `content/`. |
| Hover effects | CSS transitions (transform plus border-color), not Motion. Motion is used for entry, reveal, tabs, nav underline, count-up, typewriter, menu sheet. |
| Vercel region | Functions `gru1` (Sao Paulo), Neon project in `aws-sa-east-1`. |

## 2. Content model (Zod schemas)

Zod v4. All schemas use `.strict()` so a typo in a JSON key fails the build. File: `src/lib/content/schemas.ts`. Loaders in `src/lib/content/load.ts` read with `fs.readFile` / `fs.readdir` from `path.join(process.cwd(), 'content', ...)`, parse, and on failure throw `ContentError` with the message format `content/<file>: <path.to.field>: <zod message>`. Each loader is wrapped in React `cache()`. Content is read only at build time (all pages are static).

```ts

const PublicPath = z.string().regex(/^\/[a-z0-9/_.-]+$/);       // file under public/
const ImageRef = z.object({
  src: PublicPath,
  alt: z.string().min(5).max(160),
  fit: z.enum(['cover', 'contain']).default('cover'),
}).strict();

// Privacy guard: no phone, WhatsApp or tel links can ever be published.
const NoPhone = (s: string) => !/^tel:|wa\.me|whatsapp/i.test(s);

// content/profile.json
export const ProfileSchema = z.object({
  name: z.string(),                         // "Luiz Gustavo Lorençone Enz"
  shortName: z.string(),                    // "Luiz Gustavo Enz"
  nameLines: z.tuple([z.string(), z.string(), z.string()]), // About title, last line rendered text-subtle
  role: z.string(),                         // "Desenvolvedor Full Stack Júnior"
  roleShort: z.string(),                    // "FULL STACK JÚNIOR" (lanyard card)
  location: z.literal('Maringá, PR'),
  available: z.boolean(),                   // drives the hero badge
  heroIntro: z.string().max(320),           // hero paragraph
  bio: z.string().max(600),                 // About paragraph
  motto: z.string().max(120).optional(),    // quote card hidden when absent
  typewriterPhrases: z.array(z.string().max(40)).min(1).max(5),
  heroChips: z.array(z.string().max(24)).min(1).max(4),
  hints: z.array(z.string().max(60)).max(3), // rendered with "// " prefix
  photo: ImageRef,
  cvPath: PublicPath.endsWith('.pdf'),
  connect: z.array(z.object({
    kind: z.enum(['linkedin', 'github', 'instagram', 'site', 'email']),
    label: z.string(),                      // "LinkedIn"
    display: z.string(),                    // "in/luiz-gustavo-lorencone-enz"
    url: z.string().refine(NoPhone, 'phone links are not allowed'),

// content/experience.json  (array)
export const ExperienceSchema = z.object({
  role: z.string(),
  org: z.string(),
  start: z.string().regex(/^\d{4}(-\d{2})?$/),

}).strict();

// content/stack.json  { "items": [...] }

  name: z.string().max(40),
  monogram: z.string().min(1).max(3),
  category: TechCategory,
}).strict();
export const StackSchema = z.object({ items: z.array(TechItemSchema).min(1) }).strict();

// content/projects/<slug>.json  (slug = file name, kebab-case, validated)
export const ProjectSchema = z.object({
  title: z.string().max(60),
  kind: z.string().max(32),                 // uppercase label, e.g. "PRODUTO PRÓPRIO"
  summary: z.string().min(40).max(260),     // card (3-line clamp) and detail lead
  metaDescription: z.string().max(160).optional(), // default: summary cut at 155 chars on a word boundary
  cover: ImageRef,                          // src must be /projects/<slug>/...
  gallery: z.array(ImageRef).max(8).default([]),
  tech: z.array(z.string().max(32)).min(1).max(16), // free chips, NOT cross-referenced to stack.json
  features: z.array(z.string().min(3).max(140)).min(1).max(10),
  link: z.discriminatedUnion('status', [
    z.object({ status: z.literal('live'), url: Https }).strict(),
    z.object({ status: z.literal('private-tool') }).strict(),
    z.object({ status: z.literal('none') }).strict(),
  ]),
  repoUrl: Https.refine(u => u.startsWith('https://github.com/')).optional(),
  featured: z.boolean().default(false),
  order: z.number().int().min(0),
}).strict();

// content/certificates/<slug>.json
export const CertificateSchema = z.object({
  title: z.string().max(80),
  issuer: z.string().max(60),
  date: z.string().regex(/^\d{4}-\d{2}$/),
  image: ImageRef.optional(),
  url: Https.optional(),
```

## 3. Server and Client Component boundaries

Principle: Server Components by default; client islands are leaves that receive only primitive or small serializable props (rules `server-serialization`, `server-dedup-props`). Server-rendered content is passed into client wrappers as `children` (composition, not render props).

| component | kind | why |
|---|---|---|
| `app/layout.tsx` | Server | fonts, metadata, `<html lang="pt-BR">`, Background, SkipLink, Header, `<main id="conteudo">`, Footer. Wraps the body in `MotionProvider`. |
| `MotionProvider` | Client | `LazyMotion features={domMax} strict` plus `MotionConfig reducedMotion="user"`. Components use `m.*`, never `motion.*` (keeps the hero chunk small). `domMax` is loaded synchronously because `layoutId` is needed on first interaction. |
| `Background`, `SkipLink`, `Footer`, all `ui/*` except where stated | Server | static markup. |
| `Header` | Server shell | renders `Navbar` and passes `links` from `copy.ts`. |
| `Navbar`, `MobileMenu`, `use-scroll-spy` | Client | scroll-spy, menu state. |
| `HeroSection` | Server | text from profile; wraps children in `EntryItem` client leaves. |
| `EntryItem`, `Reveal`, `CountUp`, `Typewriter` | Client | Motion primitives (section 3.4). |
| `LanyardSlot` | Client | eligibility gate and dynamic import. `StaticLanyard` (Server) is passed to it as `children`. |
| `AboutSection`, `AboutStats` | Server | counts computed on the server; `CountUp` is the only client leaf. |
| `PortfolioSection` | Server | loads nothing itself; receives data from `page.tsx`. |
| `Tabs` (compound) | Client | tab state; panels' contents are server-rendered `children`. |
| `ProjectGrid`, `CertificateGrid` | Client (thin) | own the "Ver mais" visible count; cards are passed as pre-rendered `children` array. |
| `ProjectCard`, `TechStackGrid` | Server | static. |
| `ContactForm`, `CommentForm`, `CommentList` | Client | forms and fetch. |
| `ContactSection`, `ConnectList`, `CommentsPanel` | Server | shells. |
| `ProjectDetail` and children | Server | static detail page; `ProjectCover` uses `ViewTransition`. |

`page.tsx` loads profile, experience, stack, projects, certificates with one `Promise.all`, and reads `commentsEnabled()` from `src/lib/env.ts` (build-time boolean). Changing the comments flag needs a redeploy (documented in README).

### 3.1 Scroll-spy

`use-scroll-spy.ts(ids: readonly string[]): string | null`. One `IntersectionObserver` with `rootMargin: '-45% 0px -50% 0px'` and `threshold: 0` observing the four sections; the last section that intersects wins; at the very top (`scrollY < 8`) the result is `home`. Store the active id in `useState`; the setter only runs when the id changes (rule `rerender-derived-state`). No scroll listeners, no URL hash updates. The active link gets `aria-current="true"` and the Motion underline `m.span layoutId="nav-underline"` (300 ms expo-out; instant under reduced motion). Disabled when `usePathname() !== '/'`.

### 3.2 Mobile menu

Native `<dialog>` opened with `showModal()` (gives focus trap, Esc and inert background for free). Toggle button: 44 px, `aria-expanded`, `aria-controls`, labels from copy. Clicking a link closes the dialog and then scrolls. Sheet animation: Motion on the inner panel, 300 ms expo-out (120 ms opacity under reduced motion).

### 3.3 Tabs (compound component, rule `architecture-compound-components`)

```tsx
<Tabs.Root defaultValue="projects" label="Vitrine">        // client, owns state in context
  <Tabs.List>                                               // role="tablist", glass track, sliding pill
    <Tabs.Tab value="projects">Projetos</Tabs.Tab>          // role="tab", roving tabindex, arrows/Home/End
    <Tabs.Tab value="certificates">Certificados</Tabs.Tab>
    <Tabs.Tab value="stack">...</Tabs.Tab>                  // label "Tech Stack", mobile "Stack" via CSS
  </Tabs.List>
  <Tabs.Panel value="projects">{server children}</Tabs.Panel>
  ...
</Tabs.Root>
```

- State: `useState<'projects' | 'certificates' | 'stack'>` in `Tabs.Root` context with interface `{ state: { value }, actions: { select }, meta: { idBase } }` (rule `state-context-interface`); no URL sync (keeps `/` static and avoids history noise).
- All three panels are always mounted (`role="tabpanel"`, `aria-labelledby`, inactive ones get the `hidden` attribute) so every `aria-controls` target exists and all project links are in the initial HTML.
- Pill: `m.span layoutId="tab-pill"` inside the active tab, transition 450 ms expo-out; instant under reduced motion.
- Panel entry: when a panel becomes active it animates in (opacity 0 to 1, y 8 to 0, 300 ms micro; opacity only 120 ms under reduced motion). No exit phase (deviation D2).
- Tab selection uses `startTransition` (rule `rerender-transitions`) to keep INP low.
- "Ver mais" / "Ver menos": `ProjectGrid` and `CertificateGrid` show the first 6 items; the button renders only when there are more than 6. The stack tab always shows all groups. Certificates with 0 items render the `EmptyState` whose action selects the projects tab (`actions.select('projects')`).

### 3.4 Motion primitives (APIs frozen here so Phase 5 and Phase 6 work in parallel)

File `src/components/motion/tokens.ts` holds the easing tokens and the entry table from DESIGN.md as data:

```ts
export const EASE_EXPO_OUT = [0.16, 1, 0.3, 1] as const;
export const EASE_MICRO = [0.2, 0.8, 0.2, 1] as const;
export type EntryStep = 'background' | 'h1' | 'badge' | 'navbar' | 'typewriter' | 'paragraph' | 'chips' | 'hints' | 'scroll';
export const ENTRY: Record<EntryStep, { delay: number; duration: number; y?: number; scale?: number }>;
// values exactly as the DESIGN.md "Entry animation timeline" table (seconds)
```

Component signatures (Phase 5 uses them; Phase 6 implements the internals):

- `<EntryItem step: EntryStep as?: 'div' | 'span' | 'p' | 'h1' | 'header' | 'ul' className? children />`: absolute delay from mount, per ENTRY. Server HTML carries `data-entry` and Motion's initial inline style (opacity 0). Under reduced motion: opacity only, 200 ms, delay 0.
- `<Reveal as? index? className? children />`: viewport `amount: 0.2`, `once: true`, delay `index * 0.08`, 700 ms expo-out, y 32 to 0.
- `<CountUp value: number className? />`: renders the final value in the server HTML inside an `aria-hidden` span plus a visually hidden span with the final value; animates 0 to value on first view (1200 ms expo-out); reduced motion shows the final value.
- `<Typewriter phrases: string[] />`: `p` with `aria-label={phrases[0]}`, animated text and cursor `aria-hidden`; timings from DESIGN.md; reduced motion shows `phrases[0]` statically, cursor solid.

No-JS safety: `layout.tsx` includes `<noscript><style>{'[data-entry]{opacity:1!important;transform:none!important}'}</style></noscript>`.

Phase 5 creates these four files plus `MotionProvider.tsx` and `tokens.ts` as working pass-through versions with the exact signatures (render children, no animation); Phase 6.1 replaces their internals.

## 4. 3D lanyard architecture

### 4.1 Box and static fallback (no CLS)

`HeroSection` reserves the lanyard column with fixed dimensions, so nothing moves when the scene swaps in:

| viewport | lanyard box (w x h) | static card size |
|---|---|---|
| >= 1024 | 360 x 600, column `flex: 0 0 360px`, top = navbar bottom + 16 px | 300 x 420 |
| 768 to 1023 | 300 x 420, centered above text | 240 x 336 |
| < 768 | 100% x 330, centered | 196 x 274 |

`StaticLanyard` (Server Component) is HTML and CSS, not a raster: strap (accent div with repeated strap text, `on-accent`), clip, glass card (surface-lanyard, radius 22) with `next/image` of `/lanyard/card-photo-512.webp` (`loading="eager"`, not `priority`: the hero H1 is the LCP element), name, role, footer. It is in the initial HTML inside the box. The region wrapper carries `role="img"` only in static mode with `aria-label="Foto de Luiz Gustavo Lorençone Enz"`; in 3D mode the wrapper is a `role="region"` with the DESIGN.md aria-label and the canvas is `aria-hidden`.

### 4.2 Eligibility and loading sequence (`LanyardSlot`, client)

1. Server and first client render: `children` (StaticLanyard) only. Caption "ARRASTE O CRACHÁ" is not rendered yet.
2. After hydration, `use-lanyard-eligibility` runs once in `useEffect` and returns `'static' | '3d'`. Static if ANY of:
   - `matchMedia('(prefers-reduced-motion: reduce)').matches`
   - `navigator.connection?.saveData === true` or `matchMedia('(prefers-reduced-data: reduce)').matches`
   - `navigator.hardwareConcurrency <= 2` or `(navigator as any).deviceMemory <= 2`
   - a throwaway canvas returns null for `getContext('webgl2', { failIfMajorPerformanceCaveat: true })` and for `'webgl'` with the same option (software rendering counts as no WebGL); the test context is released with `WEBGL_lose_context`.
3. If `'3d'`: wait for the first paint (`requestAnimationFrame` twice) then `requestIdleCallback(cb, { timeout: 800 })` (fallback `setTimeout(cb, 200)`), then set `load = true`, which renders `LanyardScene` via `next/dynamic(() => import('./LanyardScene'), { ssr: false, loading: () => null })` declared at module scope of `LanyardSlot.tsx`. When `'static'`, the dynamic component is never rendered, so the chunk is never fetched.
4. `LanyardScene` calls `onReady()` after its first rendered frame. `LanyardSlot` then fades the static card out (150 ms opacity) and shows the caption. The canvas is absolutely positioned inside the same box (`inset: 0`), so there is no layout change.
5. If the scene throws (error boundary around the dynamic component) or `webglcontextlost` fires, `LanyardSlot` reverts to static permanently for the session.

### 4.3 Scene rules (Phase 6.2)

- `<Canvas dpr={[1, 1.75]} gl={{ antialias: true, alpha: true, powerPreference: 'default' }} frameloop={active ? 'always' : 'never'}>`; `active` = hero intersecting (IntersectionObserver on the hero section) AND `document.visibilityState === 'visible'`.
- `<Physics gravity={[0, -40, 0]} timeStep={1 / 60} interpolate>`; 4 segment rope (3 `useRopeJoint` plus 1 `useSphericalJoint`), joint damping 4, card is a `RigidBody` that becomes kinematic while dragged.
- `@react-three/rapier` loads `@dimforge/rapier3d-compat` (WASM inlined) through its own dynamic import inside `<Physics>`, so rapier is a separate chunk requested only after the scene chunk runs. Do not import from `@dimforge/*` anywhere else.
- Strap: `meshline` (`MeshLineGeometry`, `MeshLineMaterial` registered with `extend`), color accent `#00A7F8`, repeated text texture from `strap-texture.ts` (CanvasTexture, DM Mono 11 drawn after `document.fonts.load('11px "DM Mono"')`).
- Card: procedural rounded box (no .glb), front face texture built at runtime by `card-texture.ts` on a 1024 x 1434 2D canvas (photo, name, role, footer, same composition as `StaticLanyard`), using `/lanyard/card-photo-512.webp`. Textures and geometries disposed on unmount.
- Drei imports limited to what is used (expected: `useTexture` at most). No `Environment`, no HDR, no postprocessing. `optimizePackageImports: ['@react-three/drei']` in next.config.
- Pointer: R3F events on the card mesh; `setPointerCapture` on drag. Canvas `touch-action: pan-y` so vertical swipes still scroll the page on mobile; drag is decorative.
- Anchor at least 16 px below the navbar bottom (it is, by construction, since the box starts there and the canvas is clipped to the box).
- Camera and rest position chosen so the 3D card at rest overlaps the static card rectangle in the same box.

## 5. Contact (`/api/contact`)

Files: `src/lib/validation/contact.ts` (shared), `src/app/api/contact/route.ts`, `src/lib/email/resend.ts`, `src/components/sections/contact/ContactForm.tsx`.

```ts
export const ContactInput = z.object({
  name: z.string().trim().min(1, 'name_required').max(80, 'name_too_long'),
  email: z.email('email_invalid').max(254),
  message: z.string().trim().min(10, 'message_too_short').max(2000, 'message_too_long'),
  company: z.string().max(0).optional().or(z.literal('')),  // honeypot, checked before validation
}).strict();
```

Handler order (start independent work early, rule `async-api-routes`):

1. Reject non-`application/json` (415) and `content-length` > 8 KB (413).
2. Origin check (`src/lib/security/request.ts`): `Origin` must equal the origin of `NEXT_PUBLIC_SITE_URL`, or `https://${VERCEL_URL}`, or `https://${VERCEL_BRANCH_URL}`, or `http://localhost:3000` when `NODE_ENV === 'development'`. Otherwise 403.
3. Parse JSON. If `company` is a non-empty string: return `200 { ok: true }` and do nothing (silent honeypot).
4. `safeParse`; on failure `400 { ok: false, errors: { field: code } }`.
5. Rate limit (section 6.6) bucket `contact`: 3 per 10 min and 10 per 24 h per IP hash. Exceeded: 429 with `Retry-After`.
6. If `RESEND_API_KEY`, `CONTACT_TO_EMAIL` or `CONTACT_FROM_EMAIL` is missing: 503 `{ code: 'not_configured' }`.
7. Send with the `resend` SDK: `from: CONTACT_FROM_EMAIL`, `to: CONTACT_TO_EMAIL`, `replyTo: input.email`, `subject: 'Portfolio: mensagem de ' + name` (CR, LF and control chars stripped, 120 char cap), `text` only (no HTML body, so no HTML injection). Failure: 502 `{ code: 'send_failed' }`.
8. Success: `200 { ok: true }`. All responses `Cache-Control: no-store`.

Logging: only error codes and Resend error names. Never log the request body, the e-mail address, the IP or any env value.

Client: `ContactForm` validates with the same schema on submit (errors mapped to copy, `aria-describedby`), `fetch('/api/contact', { method: 'POST' })`, button `aria-busy` with "Enviando...", status in `role="status"`. Every error state shows the mailto fallback text from copy ("...escreva para enz.luizgustavo@gmail.com.") and the Connect list always contains the `mailto:` row, so contact works with JS disabled. No secret or env var other than `NEXT_PUBLIC_*` is reachable from client code.

## 6. Comments (Neon Postgres)

### 6.1 Driver and ORM

`@neondatabase/serverless` HTTP driver (`neon(DATABASE_URL)`) plus Drizzle ORM (`drizzle-orm/neon-http`), migrations with `drizzle-kit`.

Why: each request does one or two short queries, so HTTP (no TCP pool, no connection leaks across serverless invocations) is the right transport; Drizzle adds typed, parameterized queries with near-zero runtime weight and generates plain SQL migrations that the user can read before applying. Plain SQL with tagged templates would also be safe, but loses typed rows and migration tooling. Prisma is rejected (engine weight, cold start).

### 6.2 Schema (`src/lib/db/schema.ts`)

```ts
export const commentStatus = pgEnum('comment_status', ['pending', 'approved', 'hidden']);

export const comments = pgTable('comments', {
  id: uuid('id').primaryKey().defaultRandom(),
  name: varchar('name', { length: 40 }).notNull(),
  body: varchar('body', { length: 500 }).notNull(),
  imageUrl: text('image_url'),                      // always null in v1 (images deferred)
  status: commentStatus('status').notNull().default('pending'),
  pinned: boolean('pinned').notNull().default(false),
  ipHash: char('ip_hash', { length: 64 }).notNull(),
  createdAt: timestamp('created_at', { withTimezone: true }).notNull().defaultNow(),
  moderatedAt: timestamp('moderated_at', { withTimezone: true }),
}, (t) => [
  index('comments_public_idx').on(t.status, t.pinned, t.createdAt),
  check('comments_pinned_requires_approved', sql`NOT ${t.pinned} OR ${t.status} = 'approved'`),
]);

export const rateLimits = pgTable('rate_limits', {
  bucket: varchar('bucket', { length: 32 }).notNull(),     // e.g. 'contact:10m'
  keyHash: char('key_hash', { length: 64 }).notNull(),
  windowStart: timestamp('window_start', { withTimezone: true }).notNull(),
  hits: integer('hits').notNull().default(1),
}, (t) => [primaryKey({ columns: [t.bucket, t.keyHash, t.windowStart] })]);
```

`drizzle/roles.sql` (run once by the user as the owner role): create role `portfolio_app` with login; grant `SELECT, INSERT` on `comments`; grant `SELECT, INSERT, UPDATE, DELETE` on `rate_limits`; usage on the enum type. The deployed app connects as `portfolio_app`, so even a bug in the app cannot approve, pin or delete comments. Moderation and migrations use the owner role, locally or in the Neon console only.

### 6.3 Routes (`src/app/api/comments/route.ts`)

Both methods return 404 if `COMMENTS_ENABLED !== 'true'` or `DATABASE_URL` is missing.

`GET`: `SELECT id, name, body, created_at, pinned FROM comments WHERE status = 'approved' ORDER BY pinned DESC, created_at DESC LIMIT 50`, plus the approved count. Response `{ total, items: [{ id, name, body, createdAt, pinned }] }`. Never returns `ip_hash`, `status` or `image_url` in v1. Header `Cache-Control: public, s-maxage=60, stale-while-revalidate=300`, so an approval in the Neon console is visible within about a minute without a redeploy or a revalidation endpoint.

`POST` (order):

1. 415 if not JSON, 413 if over 4 KB, 403 on origin failure (same check as contact).
2. Honeypot field `website` non-empty, or `startedAt` (ms timestamp set when the form mounted) less than 3 s ago: return `202 { status: 'pending' }` and store nothing.
3. Normalize then validate (`src/lib/validation/comment.ts`):
   - `name`: sanitize, then 1 to 40 chars, regex `^[\p{L}\p{M}\p{N} .'_-]+$` (u flag).
   - `body`: sanitize, then 1 to 500 chars.
4. Rate limit buckets `comments:10m` 3 per IP, `comments:24h` 10 per IP, and a global key `comments:global:24h` 50. Exceeded: 429 with `Retry-After`. Rate-limit DB errors fail closed (503) for comments.
5. Insert with status `pending`. Respond `202 { status: 'pending' }`. All POST responses `Cache-Control: no-store`.
6. In `after()` (rule `server-after-nonblocking`): send a plain-text notification to `CONTACT_TO_EMAIL` through Resend with name, body, id and the two SQL lines to approve or pin (section 6.5); if Resend is not configured, skip. Also, with probability 0.02, delete `rate_limits` rows older than 2 days.

Status codes map to copy in `copy.ts`: 400 field codes, 429 "Muitos comentários seguidos...", others generic error.

### 6.4 Sanitization and XSS safety (`src/lib/security/sanitize.ts`)

Applied server side (authoritative) and client side (for the counter):

- `String.prototype.normalize('NFC')`, trim.
- Remove C0 and C1 control characters except `\n`; convert `\r\n` to `\n`.
- Remove bidi overrides and isolates (U+202A to U+202E, U+2066 to U+2069) and zero-width characters (U+200B to U+200D, U+2060, U+FEFF).
- Collapse 3 or more consecutive newlines to 2; collapse runs of spaces.
- Store the cleaned plain text. No HTML escaping on write (escaping happens at render).

Render: React text nodes only, `white-space: pre-line` for line breaks. No `dangerouslySetInnerHTML`, no markdown, no auto-linking (URLs stay plain text, which also removes the SEO incentive for link spam). Avatar initial = first grapheme via `Intl.Segmenter`, uppercased. Dates formatted on the client with `Intl.DateTimeFormat('pt-BR', { dateStyle: 'medium', timeZone: 'America/Sao_Paulo' })`. ESLint rule `react/no-danger` set to `error` repo-wide (JSON-LD is the single allowed exception, section 8.3, with an inline disable comment).

### 6.5 Moderation (admin-less, SQL only)

Pre-moderation. Owner workflow, documented in the README (Phase 8):

```sql
-- list pending
SELECT id, name, body, created_at FROM comments WHERE status = 'pending' ORDER BY created_at;
-- approve
UPDATE comments SET status = 'approved', moderated_at = now() WHERE id = '<uuid>';
-- pin (must be approved)
UPDATE comments SET pinned = true WHERE id = '<uuid>';
-- hide
UPDATE comments SET status = 'hidden', pinned = false, moderated_at = now() WHERE id = '<uuid>';
```

Justification: one owner, low volume, and pre-moderation means nothing unreviewed is ever public. An env-gated token endpoint would add an authentication surface (token leakage in shell history or logs, brute force, CSRF considerations) and code that must be security-reviewed, for no real gain over the Neon console, which already has MFA-protected login. The e-mail notification closes the "how do I know there is something to moderate" gap. Revisit only if volume grows.

### 6.6 Rate limiter (`src/lib/security/rate-limit.ts`, shared by contact and comments)

- Key: `sha256(RATE_LIMIT_SALT + ':' + ip)` hex. IP = first entry of `x-forwarded-for`, else `x-real-ip`, else the literal `unknown` (which shares one strict bucket). The raw IP is never stored or logged.
- Fixed windows via one upsert per bucket:

```sql
INSERT INTO rate_limits (bucket, key_hash, window_start, hits)
VALUES ($1, $2, date_bin($3::interval, now(), 'epoch'), 1)
ON CONFLICT (bucket, key_hash, window_start) DO UPDATE SET hits = rate_limits.hits + 1
RETURNING hits;
```

- API: `limit({ bucket, key, max, window: '10 minutes' | '24 hours' }): Promise<{ ok: boolean; retryAfterSec: number }>`. Multiple windows checked with `Promise.all`.
- Fallback when `DATABASE_URL` is absent: module-level `Map` limiter (best effort per instance), used only by contact. A DB error during contact fails open (sends) and logs `rate_limit_unavailable`; during comments it fails closed.

### 6.7 Client (`CommentsPanel`, `CommentForm`, `CommentList`)

- `CommentsPanel` (Server) renders only when `commentsEnabled()` is true; otherwise the contact card spans the row alone (layout rule in Phase 5.4).
- `CommentList` fetches `GET /api/comments` when the panel first enters the viewport (IntersectionObserver, so it is off the LCP path), shows the skeleton (`role="status"`, label "Carregando comentários"), then the list or the empty state. One fetch per page view; no SWR dependency.
- After a successful POST, the form clears and shows the pending message in `role="status"`. No optimistic insert (the comment is not public yet).
- Fields: `name` (max 40), `body` (max 500, live counter), hidden honeypot `website` (`tabindex="-1"`, `aria-hidden="true"`, `autocomplete="off"`, off-screen), hidden `startedAt`.

### 6.8 Image upload: DECISION = deferred

Not built in v1. The upload label in the DESIGN.md comments panel is not rendered (deviation D4). Reasons: images are the highest moderation and legal risk on a public form (illegal or explicit content, LGPD exposure through EXIF), they need a second storage service, and pre-moderated text comments cover the feature's purpose.

When the user opts in later (separate task 5.9, Sonnet), the spec is: Vercel Blob (`@vercel/blob`), server upload through the same POST as `multipart/form-data`; 2 MB cap enforced before reading the body; magic-byte check (JPEG `FF D8 FF`, PNG `89 50 4E 47`, WebP `RIFF....WEBP`), then `sharp` re-encode to WebP max 1200 px, which strips EXIF and GPS; `put('comments/<uuid>.webp', ..., { access: 'public', addRandomSuffix: true })`; `image_url` returned by GET only for approved rows; CSP `img-src` gains `https://*.public.blob.vercel-storage.com`; env `COMMENTS_IMAGES_ENABLED=true` plus `BLOB_READ_WRITE_TOKEN`. Account setup then: in the Vercel project, Storage, create a Blob store and connect it to the project (Vercel injects `BLOB_READ_WRITE_TOKEN`). Blobs of hidden comments are deleted manually in the Vercel dashboard.

## 12. DESIGN.md deviations and copy additions

### 12.1 Deviations (orchestrator adds a dated note 2026-10-22 to DESIGN.md for each)

- D1. Card to detail uses named View Transitions (React `ViewTransition`) instead of Motion `layoutId`; same 500 ms expo-out; reduced motion 120 ms crossfade. Reason: App Router unmounts the previous page, so `layoutId` cannot pair elements across routes.
- D2. Tab panel swap has no exit phase; the entering panel animates in (300 ms). Reason: all panels stay mounted for valid `aria-controls` and complete HTML, and INP stays low.
- D3. The WebGL canvas is created when the scene chunk arrives (after first paint and idle), not at 0 ms. The static card is visible from first paint, so the hero is never empty. The lanyard row is excluded from the plus or minus 150 ms tolerance; its target is "drop starts within 1000 ms on a fast connection".
- D4. Comments are pre-moderated and text-only in v1: the upload field is not rendered and the pending-state message in 12.2 is added.
- D5. Light theme is not shipped in v1.
- D6. Entry items use absolute per-element delays from the DESIGN.md table instead of parent `staggerChildren` (same resulting timeline; the navbar lives outside the hero tree).
- D7. Card and button hover run as CSS transitions, not Motion.
