# Phase 6.3 performance budgets report

Generated by `e2e/budgets.spec.ts` (rerun: `PLAYWRIGHT_BASE_URL=http://localhost:3113 npm run budgets` against `next build && next start -p 3113`). Date: 2026-10-22.

## Environment

- Browser: Chromium 156.0.8078.4. Headless: yes. Launch args: `--ignore-gpu-blocklist --enable-unsafe-swiftshader --use-angle=swiftshader --use-gl=angle`.
- WebGL renderer (desktop): ANGLE (Google, Vulkan 1.3.0 (SwiftShader Device (Subzero) (0x0000C0DE)), SwiftShader driver). Headless Chromium may use software rendering (SwiftShader); frame rates below are a lower bound on a machine with a real GPU and are NOT directly comparable with the 60 fps budget on hardware.
- Profiles: desktop 1440x900 (Desktop Chrome, no CPU throttle); mobile 390x844 (Pixel 7 emulation: touch, mobile UA, DPR 2.625). Mobile load metrics and INP are taken with CDP CPU throttle 4x (stated per row); entry timeline and fallback checks run unthrottled.
- No network throttling (localhost). Lighthouse was not run; LCP/CLS/TBT come from PerformanceObserver in the page (TBT = sum of (longtask - 50 ms) after FCP, within the measurement window).
- Gzip sizes are computed locally with zlib level 9 on the served bodies (server sends them uncompressed on localhost), so they approximate Vercel brotli/gzip output.
- Behaviour under test: desktop auto-loads the 3D scene on idle; mobile (coarse pointer or width < 768) shows a transparent button over the static card and loads the scene only on tap, Enter or Space. Performance marks `lanyard:import` (dynamic import starts) and `lanyard:ready` (first scene frame) are used. The 3D chunk set is JS fetched in the 3D run (desktop: normal load; mobile: after the tap) minus JS fetched in a prefers-reduced-motion run (which never loads the scene).
- Frame-time medians are compared with 16.9 ms (16.7 ms plus vsync rounding). The host is a shared Windows machine without CPU isolation: back-to-back desktop loads showed the hydration long task varying from 54 ms to 760 ms, which moves TBT and entry-timeline rows between runs; rows are real measurements of one run, not a lab-stable median.
- Budgets: first-load JS for / <= 215 KB gzip (02-architecture.md section 14); scene chunk <= 350 KB gzip with rapier WASM reported separately. "Frame time" rows sample the native requestAnimationFrame cadence of the page (it stays near 60 fps even when the render loop sleeps); the render loop itself is judged by the "rAF calls/s at rest" row.
